# The pipeline of the cohabitation case

The scripts write every data file of the case into `cases/cohabitation/data/` from three inputs: the public-use female respondent files of the National Survey of Family Growth (NSFG) in the data hub, read by one stage only; the five-row extract of the Multi100 record in `data-raw/cohabitation/multi100/`; and the person-month file that SCORE built for its replication and that Multi100 gave the five analysts, committed unchanged as `cases/cohabitation/data/score_person_months.csv` (original name `Estimation Data - Kuo (JWzJ).csv`, osf.io/b6p3j), with its provenance in its codebook. They run from the project root, in this order; `menu_options.csv` is written by hand (its rows are kept in `_planning/cohabitation/tools/write_menu_options.py`) and read by the helpers and the decision map.

| Stage | Reads | Writes |
|---|---|---|
| `01_unions.R` | the fixed-width female respondent files of NSFG 1995, 2002, 2006–2010, 2011–2013 and 2013–2015 and their SAS setup files, in the NSFG folder of the data hub | `cohab_unions.csv` (19,183 women whose first cohabitation came before any marriage, one row each) |
| `02_person_months.R` | `cohab_unions.csv` | `cohab_months.csv` (44,878 person-months of the two cohorts of the paper, in the wider window) |
| `03_spec_curve.R` | `cohab_unions.csv` | `spec_curve.csv` (the 144 specifications; about two minutes) |
| `04_reference_marks.R` | `cohab_unions.csv`, `data-raw/cohabitation/multi100/multi100_kuo_extract.csv`, `score_person_months.csv` (checked against its MD5 sum, and fetched from osf.io/b6p3j only if it is absent) | `analysts5.csv`, `reference_marks.csv`, `display_reproduction.csv` |
| `05_menu_deviations.R` | `spec_curve.csv` | `menu_deviations.csv` |
| `06_displays.R` | `cohab_unions.csv`, `score_person_months.csv` | `display_lifetable.csv`, `display_shares.csv`, `display_subgroups.csv`, `display_options.csv`, `display_inference.csv`, `display_score_file.csv` |
| `check_parity.R` | `cohab_unions.csv`, `spec_curve.csv`, `display_lifetable.csv` | nothing; stops if the estimator disagrees with survey, svyVGAM, nnet or survival, or the committed curve with a fresh fit |

`01_unions.R` is the only stage that reads the NSFG files. Its raw path sits in one line at the top: `NSFG_DIR` names the NSFG folder of the data hub, `D:/ACADEMIC/DATA/SURVEYS - national other/NSFG (USA)`, and can be set as an environment variable; the stage reads `Datasets/NSFG/*.dat` and `Datasets/NSFG/sas/*.sas` inside it, taking the column positions from the INPUT statements of the setup files. Every later stage runs from the committed files alone. Stages 04 and 06 read the SCORE file from `cases/cohabitation/data/`; stage 04 checks it against the MD5 sum of the copy that the analysts received (2b656d3814d273f4a93e29bc4f0139ef) and downloads it from the OSF only when the committed file is missing.

`_tools.R` holds the estimator that every later stage sources: the menu of the curve (`SPEC_AXES`, `OFF_CURVE`, `COMPARISONS`, `ADJUST_TERMS`, `REFERENCE`) and `fit_spec()` with its parts (`check_spec()`, `spec_unions()`, `person_months()`, `spec_frame()`, `spec_matrix()`, `fit_mlogit()`, `fit_binary()`, `meat_clustered()`, `fit_model()`, `r_multi100()`, `spec_line()`). It uses base R (stats), dplyr, tidyr and purrr only, because the downloadable workspace and the browser lab carry the same functions verbatim: the multinomial model is fitted by Newton–Raphson and the design-based errors by linearisation, both written out. A change there must be copied into the workspace helpers and the helper chunk of `cases/cohabitation/lab.qmd`, and checked again with `check_parity.R`. A change of the menu is made in `_tools.R` and `menu_options.csv` together, and is followed by stages 03, 05 and 06 and the parity check.

The curve file holds a column of the single value `t` (`stat_type`), which readr reads as logical unless the column type is given (`col_types = cols(stat_type = col_character())`). Read `cohab_unions.csv` with `caseid`, `stratum` and `psu` as character columns.

Dependencies: tidyverse for the stages; nnet for stage 04; survey, svyVGAM (with VGAM), nnet and survival for the parity check only.
